## 4. 設計判断・注意点

### 体験候補投稿の確率設計（案1採用）
- 5分tickごとに独立ガチャ: `rand() < EXPERIENCE_CANDIDATE_POST_PROBABILITY`（デフォルト0.10）
- 当選時のみDBから候補取得→AI生成→投稿。当選しなければ通常ノートガチャへ続行。
- 理由: 実装が独立しており、既存の投稿多様性を壊さない。後から確率調整がDBマスタ更新だけで即時反映される。

### rate limit の適用位置
- `scheduled-post.ts`: 睡眠フロー直後 → 通常投稿抽選の前
- `probe.ts`: `handleReplyProbe` の先頭
- 超過時は `skip` ログを出して即return。ユーザーの明示的操作（リプライ）はrate limitで止めるが、フォロー返し・リアクション確認はrate limit対象外。

### error backoff の計算式
- 失敗1回: `AI_BACKOFF_BASE_SECONDS`（300秒 = 5分）
- 失敗2回: `base * 3`（900秒 = 15分）
- 失敗3回以上: `AI_BACKOFF_MAX_SECONDS`（3600秒 = 1時間）
- 成功時: `ai_failure_streak = 0`, `ai_backoff_until = NULL`

### `experience_candidates` の有効期限
- `expires_at` は作成から3日後（`experience-scan.ts` で計算）
- `daily-cleanup.ts` の `expireOldCandidates()` で `status='expired'` に更新
