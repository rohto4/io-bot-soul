## 今回セッションの主題: カスタム絵文字分類

今回のテーマは、Misskey bot「涼凪かなめ」が使うカスタム絵文字を選別するための分類基盤づくりだった。

対象は次の2段階。

1. `Step2`: `50-work` 内の絵文字画像を `text` / `illust-text` / `illust` に一次振り分け
2. `Step3`: 一次振り分け済みの画像を、かなめのノート本文・リアクション用途に沿って用途分類

### Misskey カスタム絵文字文化の整理

作業前提として、Misskey.io のカスタム絵文字文化を確認した。

判断としては、

- リアクション文化が強い
- 「感情が即読できること」が重要
- 無表情でも態度が読めるものは有力
- 公開 bot として攻撃性・誤解・内輪性の強すぎるものは避ける

という整理で、分類ルールの基礎にした。

## Step3 の分類基準の調整

途中で、`bk=感情が薄い` という雑な定義だと、虚無顔・真顔・脱力顔のような「弱いが有効な感情/態度表現」が落ちる懸念が出た。

そこで `Step3` の基準を修正した。

### 修正前の問題

- 無表情 = 無価値 と誤読しやすい
- Misskey のリアクション文化では、虚無・真顔・じー・うーん などが普通に使われる

### 修正後の方針

- 強い感情かどうかではなく、`感情・態度・反応として読めるか` を優先
- 無表情でも態度が読めれば `bk` にしない
- `bk` は「情報ラベル・UI・無機物説明」の寄りを強める

この修正で、かなめに使わせたい「弱い温度感のあるリアクション」を残しやすくした。

## Step2 実行中に出た問題と対処

実運用では、最初の Step2 実行中にいくつかトラブルが出た。

### Vision API 制限

- fallback の `Qwen/Qwen2.5-VL-32B-Instruct` は 1プロンプトあたり4画像上限
- primary の `google/gemma-4-31B-turbo-TEE` は画像数が多いと timeout しやすい

このため、`request-image-limit=4` に固定した。

### CSV パース揺れ

モデルが

- markdown table
- ヘッダーなし CSV
- path 文字列の勝手な補正

などを返したため、パーサを緩めた上で、最終的には `relative_path` 復唱ではなく `item_id` ベースの往復に切り替えた。

### 並列化と再開

最初の設計では「判定後に即移動」だったため、並列化に弱かった。

そこで Step2 を

- classify だけ先に完了
- CSV を保存
- 後から apply

に分離して、再開性と耐障害性を確保した。
